## 📌 Project Overview

This lab builds on the **OSPF Stub Area** lab and upgrades Area 1 into a **Totally Stubby Area** using a three-router, two-area design in Cisco Packet Tracer.

- **R1** sits inside **Area 1** (internal router).
- **R2** is the **Area Border Router (ABR)** between Area 1 and Area 0.
- **R3** sits in **Area 0 (Backbone)** and acts as the **ASBR**, injecting four external routes (`192.1.65.0/24` – `192.1.68.0/24`) via static routes to `Null0`.

A regular **stub area** already removes external routes (Type 5 LSAs) but still lets inter-area routes (`O IA`) through. A **totally stubby area** also removes those inter-area routes (Type 3 LSAs), so R1 keeps only:

1. Routes **inside its own area**, and
2. **One default route** (`O*IA 0.0.0.0/0`) generated by the ABR.

The magic is a single keyword on the **ABR only**: `area 1 stub no-summary`.

## 🧩 OSPF Area Design

| Router | Role | Router-ID | Areas | Stub Command |
|--------|------|-----------|-------|--------------|
| R1 | Internal Router | 10.1.1.1 | Area 1 | `area 1 stub` |
| R2 | **ABR** | 20.1.1.1 | Area 1 + Area 0 | `area 1 stub no-summary` |
| R3 | **ASBR** | 30.1.1.1 | Area 0 | — |

**External routes injected by R3 (static → Null0):**

```
ip route 192.1.65.0 255.255.255.0 Null0
ip route 192.1.66.0 255.255.255.0 Null0
ip route 192.1.67.0 255.255.255.0 Null0
ip route 192.1.68.0 255.255.255.0 Null0
```

## 📚 Theory: Normal vs Stub vs Totally Stubby

| LSA Type | Description | Normal Area | Stub Area | Totally Stubby |
|----------|-------------|:-----------:|:---------:|:--------------:|
| Type 1 | Router LSA | ✅ | ✅ | ✅ |
| Type 2 | Network LSA | ✅ | ✅ | ✅ |
| Type 3 | Inter-area summary LSA | ✅ | ✅ | ❌ (only the default) |
| Type 4 | ASBR summary LSA | ✅ | ❌ | ❌ |
| Type 5 | External LSA | ✅ | ❌ | ❌ |
| Default route | Injected by ABR | ❌ | ✅ | ✅ |

### 🔑 Where does `no-summary` go?
- **ABR:** `area 1 stub no-summary` — this is the router that stops sending summary LSAs into the area.
- **Internal routers:** just `area 1 stub` — no change needed.

Both flavors keep the **stub flag (E-bit)** the same, so the adjacency between R1 and R2 recovers on its own.

### ✔️ Benefits
- Smallest possible routing table and LSDB for internal routers
- Minimal LSA flooding into the area
- Ideal for very low-end routers
- Every topology change **outside** the area is invisible inside it

### ⚠️ Trade-offs & Restrictions
- **Cisco-proprietary** feature (stub areas themselves are standard)
- Internal routers only know "send everything else to the ABR" — with **multiple ABRs**, routing may not be optimal
- Backbone (Area 0) can **never** be stub or totally stubby
- No ASBR (no redistribution) inside the area — use **NSSA** if you need it
- No virtual links through the area

## ⚙️ Configuration

### Step 1 — Baseline: stub area working

Area 1 is already a regular stub area (`area 1 stub` on both R1 and R2). When the change on R1 is applied, the neighbor briefly drops and re-forms:

```text
R1(config)# router ospf 1
R1(config-router)# area 1 stub

%OSPF-5-ADJCHG: Process 1, Nbr 20.1.1.1 on Serial0/0/0 from FULL to DOWN, Neighbor Down: Adjacency forced to reset
%OSPF-5-ADJCHG: Process 1, Nbr 20.1.1.1 on Serial0/0/0 from FULL to DOWN, Neighbor Down: Interface down or detached
```

### Step 2 — Discover the `no-summary` option on the ABR

```text
R2(config)# router ospf 1
R2(config-router)# area 1 stub ?
  no-summary  Do not send summary LSA into stub area
  <cr>
```

### Step 3 — Make Area 1 totally stubby (ABR only)

```text
R2(config-router)# area 1 stub no-summary

%OSPF-5-ADJCHG: Process 1, Nbr 10.1.1.1 on Serial0/0/0 from FULL to DOWN, Neighbor Down: Adjacency forced to reset
%OSPF-5-ADJCHG: Process 1, Nbr 10.1.1.1 on Serial0/0/0 from FULL to DOWN, Neighbor Down: Interface down or detached
%OSPF-5-ADJCHG: Process 1, Nbr 10.1.1.1 on Serial0/0/0 from LOADING to FULL, Loading Done
```

> ✅ The adjacency dropped at `02:54:24` and was **FULL again by `02:54:29`** — R1 needed **no** configuration change.

### Step 4 — Full reference configuration

> 🔎 *The `network` statements and R3 redistribution below are the standard configuration for this design — adjust them to match your exact lab file.*

**R1 (Internal Router)**
```text
hostname R1
!
interface Loopback1
 ip address 10.1.1.1 255.255.255.255
!
interface Serial0/0/0
 ip address 1.1.1.1 255.255.255.0
 no shutdown
!
interface GigabitEthernet0/0
 ip address 192.168.1.1 255.255.255.0
 no shutdown
!
router ospf 1
 router-id 10.1.1.1
 area 1 stub
 network 10.1.1.1 0.0.0.0 area 1
 network 1.1.1.0 0.0.0.255 area 1
 network 192.168.1.0 0.0.0.255 area 1
```

**R2 (ABR)**
```text
hostname R2
!
interface Loopback1
 ip address 20.1.1.1 255.255.255.255
!
interface Serial0/0/0
 ip address 1.1.1.2 255.255.255.0
 no shutdown
!
interface GigabitEthernet0/0
 ip address 192.168.2.1 255.255.255.0
 no shutdown
!
interface GigabitEthernet0/1
 ip address 2.1.1.1 255.255.255.0
 no shutdown
!
router ospf 1
 router-id 20.1.1.1
 area 1 stub no-summary
 network 1.1.1.0 0.0.0.255 area 1
 network 192.168.2.0 0.0.0.255 area 1
 network 20.1.1.1 0.0.0.0 area 0
 network 2.1.1.0 0.0.0.255 area 0
```

**R3 (ASBR)**
```text
hostname R3
!
interface Loopback1
 ip address 30.1.1.1 255.255.255.255
!
interface GigabitEthernet0/1
 ip address 2.1.1.2 255.255.255.0
 no shutdown
!
interface GigabitEthernet0/0
 ip address 192.168.3.1 255.255.255.0
 no shutdown
!
ip route 192.1.65.0 255.255.255.0 Null0
ip route 192.1.66.0 255.255.255.0 Null0
ip route 192.1.67.0 255.255.255.0 Null0
ip route 192.1.68.0 255.255.255.0 Null0
!
router ospf 1
 router-id 30.1.1.1
 redistribute static subnets
 network 30.1.1.1 0.0.0.0 area 0
 network 2.1.1.0 0.0.0.255 area 0
 network 192.168.3.0 0.0.0.255 area 0
```

```text
R1# show ip route
Gateway of last resort is 1.1.1.2 to network 0.0.0.0

C    1.1.1.0/24 is directly connected, Serial0/0/0
O IA 2.1.1.0/24     [110/65] via 1.1.1.2, Serial0/0/0
C    10.1.1.1/32    is directly connected, Loopback1
O IA 20.1.1.1/32    [110/65] via 1.1.1.2, Serial0/0/0
C    192.168.1.0/24 is directly connected, GigabitEthernet0/0
O    192.168.2.0/24 [110/65] via 1.1.1.2, Serial0/0/0

20.1.1.1          0   FULL/  -  00:00:30    1.1.1.2     Serial0/0/0
```

> 🔍 External `O E2` routes are already gone (stub area), but **inter-area `O IA` routes (2.1.1.0/24, 20.1.1.1/32) are still present.**

### 🔹 2. `show ip ospf` on the ABR (R2) — AFTER `no-summary`

```text
R2# show ip ospf
 Routing Process "ospf 1" with ID 20.1.1.1
 It is an area border router
 Number of areas in this router is 2. 1 normal 1 stub 0 nssa
    Area 1
        Number of interfaces in this area is 2
        It is a stub area
          generates stub default route with cost 1
        Number of LSA 3
    Area BACKBONE(0)
        Number of interfaces in this area is 2
        Number of LSA 7
```

> 🎯 **Area 1 now holds just 3 LSAs** (it held 7 in the plain stub lab). The ABR still generates the default route with cost 1.

### 🔹 3. R1 routing table — AFTER (totally stubby)

```text
R1# show ip route
Gateway of last resort is 1.1.1.2 to network 0.0.0.0

C    1.1.1.0/24 is directly connected, Serial0/0/0
C    10.1.1.1/32    is directly connected, Loopback1
C    192.168.1.0/24 is directly connected, GigabitEthernet0/0
O    192.168.2.0/24 [110/65] via 1.1.1.2, Serial0/0/0
O*IA 0.0.0.0/0      [110/65] via 1.1.1.2, Serial0/0/0

R1# show ip ospf neighbor
Neighbor ID     Pri   State     Dead Time   Address     Interface
20.1.1.1          0   FULL/  -  00:00:38    1.1.1.2     Serial0/0/0
```

> ✅ The `O IA` entries for **2.1.1.0/24** and **20.1.1.1/32** are **gone**. R1 now keeps only:
> - `192.168.2.0/24` → an **intra-area** route (R2's LAN is inside Area 1), and
> - `0.0.0.0/0` → the single default route from the ABR.

**Why is the default route cost 65?**
`64` (Serial link cost) + `1` (stub default-route cost from the ABR) = **65**

## 📊 Routing Table Evolution: Normal → Stub → Totally Stubby

OSPF-learned routes on **R1** across the two labs:

| Route Type | Normal Area | Stub Area | Totally Stubby |
|------------|:-----------:|:---------:|:--------------:|
| `O E2` external (192.1.65–68.0/24) | ✅ 4 routes | ❌ | ❌ |
| `O IA` inter-area (2.1.1.0, 20.1.1.1, 30.1.1.1, 192.168.3.0) | ✅ | ✅ | ❌ |
| `O` intra-area (192.168.2.0/24) | ✅ | ✅ | ✅ |
| `O*IA 0.0.0.0/0` default route | ❌ | ✅ | ✅ |
| **Total OSPF routes on R1** | **9** | **6** | **2** |
| Gateway of last resort | Not set | 1.1.1.2 | 1.1.1.2 |
| Config on ABR | — | `area 1 stub` | `area 1 stub no-summary` |
| Config on internal router | — | `area 1 stub` | `area 1 stub` |

> 📉 **9 → 6 → 2 routes** on the same router, with the same connectivity.

## 🛠️ Troubleshooting Notes

| Symptom | Cause | Fix |
|---------|-------|-----|
| Neighbor drops right after configuring stub | Area type change forces an adjacency reset | Wait a few seconds; it should return to FULL |
| Neighbor stays down | Stub flag mismatch between R1 and R2 | Use `area 1 stub` on R1 and `area 1 stub [no-summary]` on R2 |
| `O IA` routes still on R1 | `no-summary` missing on the **ABR** | Add it on R2 (not on R1) |
| `no-summary` typed on R1 has no effect | Only the ABR generates summary LSAs into the area | Apply it on the ABR only |
| No default route on R1 | Area not configured as stub on the ABR | Check `show ip ospf` on R2 for *generates stub default route* |
| Unreachable networks after conversion | Missing/asymmetric default route | Check gateway of last resort on R1 |

## 💡 Key Learnings

1. A **totally stubby area** blocks **Type 3, 4, and 5 LSAs**, allowing only the ABR's default route.
2. The command is **`area X stub no-summary`** and it goes on the **ABR only**.
3. Internal routers keep the plain `area X stub` — the E-bit still matches, so adjacency recovers automatically.
4. **Intra-area routes always remain** (192.168.2.0/24 stays because it is inside Area 1).
5. Default route cost = **link cost (64) + 1**.
6. The LSDB in Area 1 dropped to **3 LSAs** (vs 7 in the regular stub lab).
7. Use `area 1 stub ?` in the CLI to discover keyword options.
8. **Totally stubby is Cisco-proprietary**, while regular stub areas are standard OSPF.
9. Great for branch routers, but consider path optimality when **multiple ABRs** exist.

## 🧰 Useful Commands Cheat Sheet

```text
router ospf 1
 area <id> stub                  ! Stub area (all routers in the area)
 area <id> stub no-summary       ! Totally stubby (ABR only)
 area <id> nssa                  ! Not-so-stubby area

show ip ospf                     ! Area type, ABR role, stub default route, LSA counts
show ip ospf neighbor            ! Adjacency state
show ip ospf database            ! LSDB contents
show ip route                    ! Routing table / gateway of last resort
show ip route ospf               ! OSPF routes only
```
